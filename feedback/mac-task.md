# The scheduled task on your Mac

What the collector can't read from GitHub's servers: Steamworks' refund notes and report pages (they need your Steamworks login, so they're read in your Chrome with Claude in Chrome) and YouTube captions (YouTube blocks GitHub's servers, not a home connection). Start it with `/feedback-mac` in Claude Code (the skill in `~/.claude/skills/feedback-mac`, also a button under More), which follows the prompt below. A scheduled task in the Claude app (Scheduled → New task, this prompt, no schedule, **Run now**) works too. It opens Chrome itself; Chrome has to be signed in to partner.steampowered.com (sign in once and Steam keeps you signed in).

## Prompt

You read the data the Four Games feedback collector (GitHub Actions) can't reach itself, and save it to the private repo fourgames/feedback-data through the GitHub API. The scripts live in the website repo at /Users/danny/Documents/GitHub/website/feedback; each has a docstring explaining it. Never commit to or change the website checkout; the save scripts write through `gh api` only. Do all three parts even if one fails, then report one short line per part.

0. Update the scripts: `git -C /Users/danny/Documents/GitHub/website pull -q --rebase origin main` (if it fails because of local changes, skip it and use the files as they are).

1. Video captions. Run `python3 /Users/danny/Documents/GitHub/website/feedback/transcripts_fetch.py`. It finds every YouTube video in the data still waiting for Claude's review, reads its captions (uploaded or YouTube's automatic ones) from this home connection, and saves them as transcripts/<id>.json. On its first run it makes its own venv in ~/.cache/fourgames-feedback/venv with youtube-transcript-api. Report what it prints (e.g. "2 transcript(s) saved; 1 video(s) have no captions yet").

2. Refund notes (Claude in Chrome). Open Chrome first if it isn't running: `open -a "Google Chrome"`, then wait up to a minute for the Claude in Chrome extension to connect (retry tabs_context_mcp every 10 seconds). Load the Chrome tools with ToolSearch in one call (tabs_context_mcp, tabs_create_mcp, navigate, javascript_tool, get_page_text, tabs_close_mcp). Open a NEW tab at https://partner.steampowered.com/ . If it shows a sign-in page instead of the Steamworks partner site, stop parts 2 and 3: never type a password; report that Chrome needs to be signed in to partner.steampowered.com. Otherwise read the file /Users/danny/Documents/GitHub/website/feedback/refunds.js and run its full contents with javascript_tool in that tab; it returns the length of a JSON string kept in window.__refundNotes (it can take a minute). Read it out in parts of 800 characters with `window.__refundNotes.slice(0, 800)`, `.slice(800, 1600)` and so on until the whole length is read, join the parts exactly (no added characters) and write them to a temporary file, check it parses as JSON, then run `python3 /Users/danny/Documents/GitHub/website/feedback/refunds_save.py <that file>` and report what it prints.

3. Steamworks stats, in the same tab (navigate it back to https://partner.steampowered.com/ first). Read /Users/danny/Documents/GitHub/website/feedback/steamworks.js and run its full contents with javascript_tool. It returns at once and works in the background; check `document.title` every 20 seconds or so until it is "steamworks ready" (or starts with "steamworks failed:", then report that error and skip the save). It can take a few minutes. Then use get_page_text on the tab (with a large max_chars), write the full text to a temporary file (it must end with the line END; if the text is cut off, read it with javascript_tool as `document.querySelector('pre').textContent.slice(...)` in parts instead) and run `python3 /Users/danny/Documents/GitHub/website/feedback/steamworks_save.py <that file>`; report what it prints.

4. Close the tab you opened. Don't touch the user's other tabs. Delete the temporary files.
